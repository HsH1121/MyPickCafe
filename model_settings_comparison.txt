  항목별 설정 차이와 장단점

1. temperature
------------------------------------------------------------------
설정값   Dummy=0.0  /  FastAPI=0.1

Dummy  (0.0)
  장점 - 완전 결정론적. 동일 리뷰를 반복 실행해도 결과 일정 → 재현성 높음
       - 배치 대량 생성 시 일관성 확보에 유리
  단점 - 경계가 애매한 케이스에서 틀린 방향으로 고집 (Case 12 MODERN 오탐 반복)

FastAPI  (0.1)
  장점 - 약간의 유연성으로 모호한 표현에서 더 자연스럽게 처리 가능
  단점 - 비결정론적 → 실행마다 결과가 미세하게 달라질 수 있음
       - Case 13처럼 없는 태그를 생성하는 오탐 발생 가능성


2. num_predict (최대 출력 토큰)
------------------------------------------------------------------
설정값   Dummy=1000  /  FastAPI=768

Dummy  (1000)
  장점 - 배치 10개 결과를 한 번에 담아야 하므로 넉넉한 토큰 필요
       - MENU Recall 1.00 — 토큰 부족으로 인한 누락 없음
  단점 - 단건 처리 시 불필요한 토큰 낭비, 응답 속도 소폭 저하

FastAPI  (768)
  장점 - 단건 처리에 768으로 충분, 응답 속도 약간 빠름
  단점 - 복잡한 리뷰에서 출력이 잘리면 뒤쪽 태그 누락 가능
       - Case 12 BAKERY 누락의 원인 중 하나로 추정


3. top_p
------------------------------------------------------------------
설정값   Dummy=없음(기본값)  /  FastAPI=0.9

Dummy  (기본값)
  장점 - 별도 설정 없이 동작, 단순함
  단점 - 모델 기본값에 의존 → MOOD 오탐(MODERN) 발생
       - 허용 목록 외 이상한 태그가 섞일 가능성 있음

FastAPI  (0.9)
  장점 - 상위 90% 확률 토큰만 사용 → 허용 목록 외 오탐 억제
       - MOOD FP 0건 — top_p가 실제로 오탐 억제에 효과적
  단점 - 지나치게 보수적인 경우 정상 태그도 억제될 수 있음


4. 프롬프트 구조
------------------------------------------------------------------
               Dummy                   FastAPI
태그 키        FACILITY/MENU/MOOD       facilityTags/menuTags
               /PURPOSE                /moodTags/purposeTags
few-shot 예시  7개 (부정 케이스 중심)   8개 (mood·sentiment 포함)
감성 분석      없음                     sentiment: GOOD/BAD/null

Dummy
  장점 - 태그 추출에만 집중, 프롬프트 간결 → 모델 집중도 높음
  단점 - 감성 정보 없음 → 리뷰 품질 분류 불가

FastAPI
  장점 - 감성 분석까지 단일 호출로 처리 (13/13 = 100% 정확)
  단점 - 출력 항목이 많아 복잡한 리뷰에서 일부 태그 누락 가능성
       - 프롬프트가 길어 모델 처리 부담 소폭 증가
